## E0：初始基线

**假设**：仅靠混合检索和抽取式生成器，可以在小型企业语料上达到可接受的来源命中与引用质量。

**配置**：无问题覆盖门槛；第二来源只要句子分数达到主来源的 72% 就加入；不区分“相关”和“足以回答”。

**结果**：

| 指标 | 数值 |
|---|---:|
| 通过 | 17 / 20（85.0%） |
| 来源命中率 | 100% |
| MRR | 1.000 |
| 关键词覆盖 | 94.4% |
| 引用准确率 | 64.8% |
| 拒答正确率 | 0% |
| 注入抵抗率 | 100% |
| 延迟 p95 | 8.02 ms |

**失败**：

- `q002`、`q005`：答案正确，但额外引用了 `it-support-sop.md` 或 `procurement-expense.md`。原因是与问题共享“工作日”等泛化词，72% 阈值过宽。
- `q019`（股票代码）：知识库无答案，却因为命中“公司”“代码”等常见词而被回答。混合分数 0.304，高于 0.22 门槛。

**归因**：

1. 生成器的“来源多样性”没有区分“补充新信息”与“共享背景词”。
2. 绝对相关性分数受语料和查询长度影响，不能单独作为可回答性判断。

## E1：引用约束 + 绝对词面门槛

**改动**：

1. 第二来源必须补充至少 2 个主来源不存在的问题词项，才允许加入。
2. 只从已选来源中补齐第 3 句，避免第三篇无关文档进入引用。
3. 增加 `min_top_lexical_score=0.55`，用顶层 BM25 归一化分数拦截 `q019`。

**结果**：20/20，引用准确率 100%，拒答 100%。但单文档知识库测试出现误拒答：当 `N=1` 时 BM25 的 IDF 被压缩，`lexical_norm` 天然偏低，合法问题也达不到 0.55。

**结论**：绝对 BM25 阈值依赖语料规模，不可作为通用门槛，方案被回滚。

## E2：语料规模无关的覆盖率门槛

**改动**：

1. 删除 `min_top_lexical_score`。
2. 增加 `min_query_coverage=0.30`：
   ```text
   coverage = |query_tokens ∩ retrieved_context_tokens| / |query_tokens|
   ```
3. 保留 E1 的引用来源约束。
4. 修正 `q010`：原问题只问“多久内联系”，却把“远程擦除”列为期望关键词，题目与期望不一致；改为“应采取哪些措施，安全团队会做什么？”，让两步处置都成为合理期望。
5. 提示清洗增加 `</context>` 与特殊 token 移除。

**结果**：

| 指标 | 数值 |
|---|---:|
| 通过 | 20 / 20（100%） |
| 来源命中率 | 100% |
| MRR | 1.000 |
| 关键词覆盖 | 100% |
| 引用准确率 | 100% |
| 拒答正确率 | 100% |
| 注入抵抗率 | 100% |
| 延迟 p50 | 7.7 ms |
| 延迟 p95 | 9.2 ms |

`q019` 的覆盖率约 14%，低于 30% 门槛，被拒答；合法题目的最低覆盖率约 47%，与门槛之间仍有可观测间隔。

**结论**：覆盖率门槛解决了小语料下的尺度依赖，同时保持拒答能力。当前基线 100% 是“容易集 + 抽取式生成器”的结果，不代表开放域能力。

## E3：制度版本与生效日期

**假设**：企业制度会持续换版，单靠相似度检索会把旧版答案当成当前答案；把生效窗口纳入检索契约后，可以同时支持当前问答和历史审计。

**改动**：

1. 文档增加 `policy_key`、`version`、`effective_from`、`effective_until`。
2. 写入时校验同一 `policy_key` 的生效窗口不能重叠，冲突返回 409。
3. `/chat` 和 `/documents` 支持 `as_of`；`RAGPipeline` 默认使用服务器当天日期。
4. 引用返回版本号和生效日期，答案可审计到具体版本。
5. 增加 `employee-handbook-2025.md`，与 2026 版形成非重叠窗口。
6. 评测集 20 题全部固定 `as_of: 2026-06-01`，避免系统时钟变化导致基线漂移。

**验收结果**：

| 场景 | 结果 |
|---|---|
| `as_of=2025-06-01`，问三年年假 | 返回 8 天，引用 2025 版 |
| `as_of=2026-06-01`，问三年年假 | 返回 10 天，引用 2026 版 |
| 重叠 `employee-handbook` 窗口 | HTTP 409 |
| `policy_key` 缺少生效日期 | HTTP 422 |
| 20 题基线 | 20/20，质量门禁 PASS |
| 延迟 | p50 7.7 ms，p95 8.4 ms |

**结论**：这个功能把“制度过期”从提示词问题变成了检索约束和数据校验问题，适合制度、合规、HR 等强时效知识库。

## 决策记录

1. **来源级引用优先于句子级归因**：实现成本低，先建立回归基线；句子级归因列入 E5。
2. **保守拒答优先于猜测**：企业制度问答中，错误答案的代价高于拒答；因此覆盖率门槛偏低（0.30）但配合显式拒答文案。
3. **保留抽取式生成器**：可解释、无外部依赖，是检索质量的上界近似，也是 LLM 生成器的对照。
4. **评测数据入库到 Git**：20 题和基线报告都提交，CI 可比较，不依赖外部评测平台。
5. **不提交数据库**：`data/*.db` 和评测 artifacts 不提交，只提交小型 `baseline.json`。
